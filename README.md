# 电脑世界探索器（ByteAtlas）

把真实文件系统解释为可以俯瞰、缩放、逐层探索的微缩城市。

当前阶段：阶段 3 首版稳定性修复、状态交互完善与 0.2.0 验收。真实目录闭环之上已实现监听核对、活动模式、Git 标记、schema 3 迁移与后台恢复；0.2.0 的 NSIS 候选产物、项目图标和 Windows 版本资源已生成，但未签名。当前候选已在正常桌面宿主完成解包 smoke、隔离安装副本 smoke、硬件桌面目录基准及 0.1.0→0.2.0 数据保留升级；24 小时监听耐久正在运行，跨版本卸载仍有一次真实失败记录，不能据此称为首版交付完成。2026-09-12 已完成一个待用户目视评审的核心城市体验样板（主画布、抽屉、模型族和连续探索），不等同用户认可或完整验收。实现、历史验证和未通过项目见 [阶段 3 记录](Docs/Stage-3.md)，性能口径见 [性能记录](Docs/Performance.md)。

## 已确定的方向

- 首版仅支持 Windows。
- 默认明亮、温暖的微缩模型城市；预留深色科技主题切换能力。
- 文件夹是街区，文件是建筑，Git 仓库是工业园区，文件大小影响建筑高度，近期修改活动形成暖色提示。
- 每层目录一张沙盘，布局稳定，按视距与规模聚合。
- 技术栈：Electron、TypeScript、React、Three.js、SQLite。
- 首版读取选定范围的目录结构和元数据，在本地索引；提供搜索、打开、定位，不提供文件修改操作。

## 探索真实目录

首页选择文件夹，阅读范围说明后点击“开始探索”。扫描期间可浏览已发现内容、暂停或取消；重开世界先显示缓存并重新核对。未知或失败范围会标明不完整，不展示虚假的完整容量。

直属文件通过稳定聚合组和分区分页展示，搜索支持中文、单字符与路径片段，并可揭示组内文件。相机、选择、配色、模式和布局保存到应用本地数据库。文件详情提供默认程序打开、资源管理器定位和复制路径；双击文件不会启动程序。移除世界只移除应用记录。

只读取结构和元数据，不跟随目录链接，不静默排除依赖目录。应用自身数据目录处于扫描范围时会明确排除；当前不提供自定义排除编辑器。统计为逻辑大小，硬链接可能重复计入。最近启动扫描的世界会监听变化并周期核对；取消扫描会停止该世界监听。活动模式提供最近 24 小时的修改/变化推断，不代表真实读写流量。

## 探索样例城市

首页可另行进入虚构的“我的工作空间”，包括 111 个文件与 10 个目录（含根目录），明确标注“未扫描电脑”。

- 左键拖动平移、滚轮缩放、右键拖动旋转；双击街区进入，返回恢复镜头与选择，画布内“俯瞰”可重新取得方向。
- 单击建筑或按需展开的目录列表查看详情；目录也有独立进入按钮，键盘可访问，图形失败时仍可用该同源列表。
- 搜索支持样例中文名称与路径；尝试“素材母版”或“贴图_001”。
- 素材仓库把 96 个文件聚合为 6 个稳定编号的组；从成员列表可临时展开单个文件。
- 切换容量/活动/类型模式、日光/暖暮配色不会改变布局；活动样例明确是近期变化演示，不是实时读写。暖暮仅用于验证主题边界，不是完整科技主题。
- 建筑高度使用固定压缩尺度；目录缩略建筑仅表达概况，类型模式中街区使用文件数量最多的类型。

样例布局独立保存到应用浏览器存储，示例文件没有系统打开动作，与真实世界索引分离。

## 开发与验证

开发环境：Windows x64、Node.js 24.15+（24.x）、npm 11.x。依赖精确锁定，使用 `package-lock.json`。首版兼容目标为 Windows 10 22H2 / Windows 11 x64；目前只在 Windows 11 build 22631 上验证，不宣称 Windows 10 已通过测试。

```powershell
npm ci
npm run setup:electron
npm run dev
```

Electron 44 的 npm 包按需获取运行时；首次离线启动前先完成 `setup:electron`。不需要全局安装构建工具，不改动用户的 npm registry 或代理设置。

| 命令 | 用途 |
| --- | --- |
| `npm run typecheck` | 后台、preload 与浏览器界面分别做类型检查 |
| `npm test` | IPC、SQLite、确定性布局、聚合与大小映射测试 |
| `npm run build` | 类型检查并构建到 `out/` |
| `npm start` | 运行已构建版本 |
| `npm run smoke` | 对已构建版本执行两次隐藏窗口数据库与沙盘自检 |
| `npm run smoke:dev` | 验证 Vite 开发服务、CSP 和桌面通信，自动退出 |
| `npm run pack` | 构建并生成 `dist/win-unpacked/ByteAtlas.exe` |
| `npm run dist` | 构建 Windows x64 NSIS 安装器，不自动发布 |
| `npm run smoke:packaged` | 对解包应用执行两次隐藏窗口自检 |
| `npm run benchmark:catalog` | 自有 1 万、10 万、密集 2 万文件负载；普通测试默认跳过此慢测试 |
| `npm run benchmark:desktop-catalog` | 自有 1 万文件/100 目录 fixture 的完整 Electron 进程硬件基准；测扫描、可见对象、rAF 间隔和进程集工作集 |
| `npm run benchmark:graphics` | 独立硬件窗口测量样例镜头及图形故障恢复 |
| `npm run verify:upgrade -- --previous=<旧安装器> --current=<新安装器>` | 在 `.artifacts` 的独立目录先静默安装旧版、再同目录安装新版，检查数据库与已保存视角；两个参数均为必填安装器路径 |
| `npm run verify:install -- --installer=<当前安装器>` | 在 `.artifacts` 隔离目录安装、运行当前候选并静默卸载；必填参数为安装器路径 |
| `npm run verify:listener-endurance -- --duration-ms=86400000 --sample-ms=300000` | 可恢复的 24 小时监听耐久入口；只操作 `.artifacts` fixture，并在文件系统阶段后执行一次解包 Utility Process 恢复自检 |

自检数据库、浏览器缓存、报告与截图保存在独立的 `.artifacts/` 子目录；目录测试只扫描在其中创建的自有 fixture。smoke 截图使用软件离屏绘制，不代表 GPU 性能；graphics 基准单独使用硬件加速。普通运行使用 Electron 的应用本地数据目录并启用硬件加速。

运行 `dist/win-unpacked/ByteAtlas.exe` 时必须保留整个 `win-unpacked` 目录。当前候选产物为 `dist/ByteAtlas-0.2.0-windows-x64-setup.exe`：已嵌入 ByteAtlas 图标和 0.2.0 Windows 版本资源，SHA-256 为 `DFF441E83A60338CBEF0D91A73552AFAA1252C05B8BD0BF4B4E153CCB71B5EC1`，Authenticode 为 NotSigned。此前 `-1073741515` / `STATUS_DLL_NOT_FOUND` 只在受限执行环境中复现；同一最小安全 Electron 窗口也失败，而正常桌面宿主中的当前解包及安装副本均已启动，因此没有把它归因为项目包缺文件或显卡驱动。2026-09-12 的当前候选安装、两次启动、静默卸载和 profile 保留已在 `.artifacts/installation-OKqDzU/` 通过；`0.1.0→0.2.0` 升级的数据快照与启动恢复在 `.artifacts/upgrade-ypOBB8/` 通过，但严格脚本以非零结果记录该次最终卸载留下 `ByteAtlas.exe`，仍是待修复的失败证据。2026-09-11 的 0.1.0 安装、同版本覆盖和卸载仅为历史证据。未签名、24 小时监听未完成以及兼容性/ACL 未验证，均阻止将候选称为正式发布版。
