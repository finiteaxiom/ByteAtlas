## 阶段 0：工程准备

交付：锁定依赖和构建方式、Windows 支持范围、模块骨架、SQLite 与后台进程最小验证、测试硬件记录。

进入阶段 1 前验证：打包环境中后台进程能启动并正常退出；数据库可创建、写入与重开；渲染界面无法直接访问文件系统；日志不记录文件正文，路径信息限制在必要诊断范围。

用户已授权工程准备。阶段 0 不扩展实现目录扫描、城市沙盘或正式安装器。

## 阶段 1：固定数据沙盘

交付：温暖主题、确定性布局、目录进入、相机恢复、选中详情、聚合与临时揭示、容量与类型视觉编码。

验证样例包含空目录、长名称、中文、零字节和超大文件、深层目录、密集同类文件。

验收：

- 同一数据集生成结果确定；增删少量文件不会使无关街区换位。
- 返回恢复镜头与选中，滚轮不改变目录层级。
- 文件与聚合组可明确区分，聚合数量与成员一致。
- 高度与大小单调对应，不因主题或进入目录而重新归一化。
- 主题测试参数切换后布局、镜头、选择和数值不变。
- 人工视觉检查温暖城市的轮廓、标签、活动/选中区分与遮挡；不能只以逻辑测试通过认定观感达标。

## 阶段 2：真实目录闭环

交付：根目录选择、渐进扫描、暂停取消、本地索引、中文片段搜索、定位打开、布局持久化。

验收：

- 扫描未完成时可以浏览，未知统计不显示为零或完整值。
- fixture 的目录项、逻辑大小与独立枚举结果一致；排除项与链接策略明确。
- 中文、单字符、名称片段、路径片段命中预期结果；旧查询不会覆盖新查询。
- 搜索到聚合内部文件后可见并选中，返回恢复原位置。
- 特殊字符、空格、中文路径能够正确定位，不被解释为 shell 命令。
- 无权限、根目录离线、取消扫描不导致已有索引批量误删。
- 应用重开后恢复缓存与镜头，并显示重新核对状态。
- 扫描与搜索不读取文件正文；自有索引不会写入选定项目。

## 阶段 3：首版完善与交付

交付：文件监听与核对、活动模式、Git 标识、异常恢复、性能调整、Windows 安装产物。

验收：

- 创建、修改、删除、改名、移动均在核对后与真实目录一致；无法识别改名时允许删除加新增，但不留下重复项。
- 大批事件合并更新，镜头不跳动；监听异常后能重新核对。
- Git 的 `.git` 目录与文件标记均能识别；不执行仓库命令或改写仓库。
- 初次扫描及普通刷新不制造虚假“刚刚新增”活动。
- 删除当前选中文件后详情明确变为不可用，不能打开过期路径。
- 后台进程异常、图形上下文丢失、根目录离线均有可理解状态与恢复入口。
- 打包后验证扫描、SQLite、搜索、系统打开、正常退出，以及升级后应用数据迁移。

## 性能验证方法

以下是拟定测试负载，不是已证实的容量承诺：

| 负载 | 建议规模 | 验证重点 |
| --- | --- | --- |
| 普通项目树 | 约 1 万目录项 | 首次呈现、搜索、日常镜头操作 |
| 大型目录树 | 约 10 万目录项 | 索引速度、峰值内存、暂停响应 |
| 密集单目录 | 约 2 万文件 | 聚合、分页、拾取、标签预算 |
| 高频变更 | 批量增删改 | 队列有界、收敛时间、无全量重排 |

在阶段 0 记录 CPU、GPU、内存、Windows 版本、磁盘类型、分辨率、数据集和冷/热缓存条件。进入阶段 2 前依据阶段 1 实测固定首屏、帧时间、搜索延迟、取消响应、内存与变化收敛的数值门槛。

每次报告标明扫描期间/空闲期间、可见实例数以及样本规模。不能用平均帧率代替卡顿分布，也不能把尚未扫描范围计入完整搜索。

## 测试边界

- 纯逻辑：布局稳定性、大小映射、统计完整性、聚合成员、搜索过期结果处理。
- 临时目录集成：权限/消失/链接/变更、索引迁移、取消与恢复；不通过破坏用户真实文件验证。
- 桌面端到端：选择、导航、搜索、详情、系统定位和启动恢复。
- 人工视觉与性能：温暖主题辨识、相机手感、遮挡和真实机器指标。

设计文档检查不等同于这些测试。每阶段的完成报告必须区分已实现、已验证、未验证及已知限制。
